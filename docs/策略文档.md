## 3. 技术策略与关键决策

### 3.1 依赖限制（硬约束）

允许：Python 标准库 + `langdetect` + `openpyxl` + `chardet`。
禁止：`PyQt` / `litellm` / `asyncio` / `playwright` 等重型库。
理由：保持工具离线、零成本、可独立分发 [source:agents-md:AGENTS.md:56-59]。

### 3.2 OCR 四级模式

| 模式 | 独立噪音 | 嵌入碎片 | 语义安全 | 适用 |
|------|---------|---------|---------|------|
| `flag-only`（默认） | 不处理 | 不处理 | 完全 | 先观察污染程度 |
| `clean-mark` | `[?]` 标记 | `[?]` 标记 | 完全 | 需清洗但保语义 |
| `clean-light` | 删除 | `[?]` 标记 | 较安全 | 精细清洗 |
| `clean-aggressive` | 删除 | 删除 | 会破坏 | 下游有修复能力 |

来源：[source:agents-md:AGENTS.md:81-88]。

### 3.3 净字符口径（net_char_count）

剥除以下噪音后的字符数，反映移动端实际需渲染的内容量 [source:agents-md:AGENTS.md:90-96]：

- Markdown 标记（`#` / `**` / 列表符）
- HTML 标签（`<tag>` / `<table>` 整套）
- Markdown 图片 `![](path)` / 链接语法仅保留 text
- 代码块围栏 ` ``` `（内容保留）
- 连续空白合并为 1 空格

长度档位基于 `net_char_count`：≤20K=S, 20K-50K=M, >50K=L [source:omo-plan:corpus-cleaner.md:84-91]。

### 3.4 表格过滤阈值

`table_ratio`（含 `<table>` 行 / 总行数）> `0.70` → 隔离至 `_tables/{AR|RU|FR|EN}/` [source:agents-md:AGENTS.md:98-99] [source:omo-plan:corpus-cleaner.md:95]。

### 3.5 命名规范（Stage 5）

文件名：`{category}_{topic}_{seq:03d}_{S|M|L}.md` [source:agents-md:AGENTS.md:75-79]。

- `category` 按优先级：`exam` / `tutorial` / `book` / `lecture` / `short` / `table` / `misc`
- `topic` 来自首个 `#` / `##` / 前 20 行非空行 / 兜底 `untitled`
- 长度档位基于 `net_char_count`

### 3.6 输出结构（Stage 6）

```
corpus_cleaned/
  {AR,RU,FR,EN}/<new_name>.md       # 通过文件按语言归类
  _tables/{lang}/<original>.md       # 表格过滤
  _contaminated/{lang}/<original>.md # OCR 污染隔离
  _duplicates/{exact,suspected}/    # 去重
  _empty/
  _bad_files/
  _report.xlsx                       # 6 张工作表
  _summary.txt
  _original_manifest.json
```

来源：[source:agents-md:AGENTS.md:61-73]。

### 3.7 合法双语白名单

不视为 OCR 污染的 6 类内容 [source:agents-md:AGENTS.md:101-107]：

1. URLs: `https?://\S+`
2. Emails: `\S+@[a-zA-Z0-9._-]+\.[a-zA-Z]+`
3. Markdown 代码块内容
4. 全大写英文缩写（3+ 字符）：`\b[A-Z][A-Z0-9_]{2,}\b`
5. 数字 + 单位：`\d+(\.\d+)?\s*(%|[a-zA-Z]+)`
6. 图片标签 / HTML 属性

## 5. 运行与验证

### 5.1 启动命令

```bash
python corpus_clean.py --input <folder> --output corpus_cleaned/ \
  [--ocr-mode flag-only] [--length-thresholds 20000,50000] [--fuzzy-dedup]
```

来源：[source:agents-md:AGENTS.md:114-116]。

CLI 参数说明：

- `--input`：5 个用户回流文件夹之一
- `--output`：默认 `corpus_cleaned/`
- `--ocr-mode`：默认 `flag-only`（最保守）
- `--length-thresholds`：S/M/L 阈值，默认 `20000,50000`
- `--fuzzy-dedup`：开启内容近似重复检测（min-hash Jaccard > 0.95，默认关闭）

## 6. 已知限制与风险

1. **Plan 状态 awaiting-approval，尚未开始实现** [source:agents-md:AGENTS.md:111]：`corpus_clean.py` 入口和 `corpus_cleaner/` 子包尚未实现，目前仅有 `__init__.py` 0 字节占位 [source:agents-md:AGENTS.md:35]。影响范围：全项目，所有功能待实现。

2. **null-byte 污染未修复**：真实 AR 语料文件内容含 `\x00`（null bytes），通过 pipeline 传播至 `reporter._sheet_file_details()` 写入 openpyxl 单元格时触发 `IllegalCharacterError` [source:omo-notepad:issues.md:10-23]。修复方案：`renamer._sanitize()` 应剥除 C0 控制字符（U+0000-U+001F，保留 `\t` `\n` `\r`），或在 `reporter._write_excel()` 单元格写入前做防御性 sanitize [source:omo-notepad:issues.md:21-22]。状态：Known，合成数据测试通过；真实数据测试标记 `xfail` [source:omo-notepad:issues.md:20]。影响范围：真实 AR 数据上 pipeline 无法完成。

3. **safe_filename 与 plan 矛盾**（已解决）：`utils.py:safe_filename()` 将非 ASCII（Arabic/CJK/Cyrillic）替换为 `_`，与 plan Stage 5 "Unicode 字符保留（Windows 原生支持）" 要求冲突 [source:omo-notepad:issues.md:5-9]。解决方案：T8（Renamer）的 `renamer._sanitize()` 用 `[A-Za-z]+` Latin-only regex 进行小写化，仅匹配 ASCII 字母（无 `re.UNICODE` flag），从而保留 Unicode 字符；`safe_filename()` 保留为保守的 ASCII-only 兜底 [source:omo-notepad:issues.md:8]。状态：已修复。

4. **文档与运行状态可能不同步**：T3 挖掘笔记记录 T1-T14 全部完成 + 生产运行结果（3280 文件，14h 9m），但 AGENTS.md 与 notepad issues.md 尚未同步至该状态 [source:inference:project-dev-docs/task-3/corpus-mining-notes.md:96-115]。建议以 live notepad / AGENTS.md 为权威源，待项目方同步后再修订本文档。
